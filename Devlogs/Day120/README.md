# Project Delta - 120일차 개발일지

## 작업 개요

117~119일차에 걸쳐 만든 별도 이벤트 전투(구조·행동 12종·주도권·상성·숙련도·다수 참가자)를 실제 게임에서 안전하게 쓸 수 있도록 마무리하는 날이다. 핵심은 두 가지다.

1. 저장/복구 - 이벤트 전투 도중 저장하면 다시 켰을 때 안전하게 이어지게 한다.
2. 화면 재구성 - 지금까지 쌓인 정보(대상별 게이지, 자원, 상성, 로그, 아이템)를 한눈에 보기 좋게 배치한다.

---

## Part 1. 저장/복구

`Assets/ProjectDelta/Scripts/Data/EventBattleCheckpointStore.cs`(신규), `RunData.cs`, `ApplicationFlow.cs`

- 82일차 `BattleEncounterCheckpointStore`와 완전히 같은 원칙을 따르는 이벤트 전투 버전을 만들었다 - 정확한 턴 단위 재현은 시도하지 않고, "저장 시점에 이벤트 전투가 진행 중이었다"는 사실과 그 시점의 수치(방 ID·진입 경로·대상별 호감도/단계·플레이어 자원·시도 횟수)만 남긴다.
- 이벤트 전투는 이미 진행 중이던 일반 전투 안에서 열리므로(유혇 성공 등), 복원 시점엔 이 체크포인트를 로그로 한 번 남기고 비운다 - 일반 전투 체크포인트가 같은 조우를 처음부터 다시 열어준다. 완벽한 재현 대신 "안전하게 되돌아간다"를 택했다 - 82일차 것도 원래 이런 방식이라 통일했다.
- `ApplicationFlow`의 새 게임 시작·이어하기·저장·패배·런 포기 지점 전부에 `BattleEncounterCheckpointStore`와 나란히 연결했다.

## Part 2. UI 전면 재구성

`Assets/ProjectDelta/Scripts/Presentation/EventBattleController.cs`

사용자 요청대로 "전반적으로 UI 배치를 재구성"했다. 117~119일차에 쌓아온 정보(대상 최대 3명, 자원, 상성, 숙련도)를 세로로 쌓기만 하던 걸 2단 레이아웃으로 다시 짰다.

- **왼쪽 열** - 대상 명단을 세로 상자로 쌓았다. 각 상자에 이름·미니 호감도 게이지·상태(이탈/성공/보스 단계)를 보여주고, 선택된 대상은 테두리와 큰 게이지로 강조한다. 그 아래 플레이어 MP/정력을 실제 채워지는 막대로 보여주고, "지금 차례: 플레이어/상대" 배지를 추가했다.
- **오른쪽 열** - 행동/아이템 탭으로 화면을 나눴다. 행동 그리드는 3열로 줄여 폭에 맞췄고, 선택된 대상에게 강점/약점인 행동이면 이름 옆에 `[강점]`/`[약점]` 태그를 붙인다(118일차에 만든 상성 필드는 아직 실제 데이터가 없어서 대부분 아무 표시도 없다 - 133~135일차 몫). 스크롤되는 전투 로그(최근 6줄)를 추가해 상태 텍스트 한 줄로만 보이던 걸 히스토리로 볼 수 있게 했다. 포기 버튼은 맨 아래 고정.

## Part 3. 아이템 사용

93일차 `ItemUseService.CommitBattle`을 그대로 재사용했다 - 이벤트 전투의 `Player`가 진짜 `BattleParticipant`라 새 코드 없이 바로 연결됐다. 자기 차례에만 쓸 수 있고, 호감도에는 영향을 주지 않지만 자원 회복 후 턴을 소모한다.
