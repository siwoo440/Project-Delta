# Project Delta - 80일차 개발일지

## 개발 목표

전투 승리 시 실제로 처치한 몬스터 구성을 기준으로 골드와 아이템 드롭을 판정하고, 이후 정식 보상 화면에서 재추첨 없이 사용할 수 있는 전투 드롭 결과를 보존하는 구조를 구현한다.

## 구현 내용

### 1. 몬스터별 드롭 테이블 구조 추가

`MonsterDropTable`과 `MonsterDropEntry`를 추가했다.

각 몬스터는 독립된 드롭 테이블을 가질 수 있으며 다음 값을 설정할 수 있다.

- 최소 골드
- 최대 골드
- 드롭 아이템
- 아이템 드롭 확률
- 최소 드롭 수량
- 최대 드롭 수량

드롭 확률은 `0~10000`의 basis point 방식으로 관리한다.

- `10000` = 100%
- `5000` = 50%
- `100` = 1%

### 2. MonsterDefinition과 드롭 데이터 연결

`MonsterDefinition`에 `MonsterDropTable` 참조를 추가했다.

80일차 설치 작업을 통해 현재 등록된 몬스터 정의마다 개별 DropTable이 생성되고 연결되도록 구성했다.

기본 골드 범위는 다음과 같다.

| 등급 | 최소 골드 | 최대 골드 |
| --- | ---: | ---: |
| 일반 | 5 | 12 |
| 희귀 | 15 | 30 |
| 보스 | 40 | 80 |

실제 아이템 콘텐츠가 아직 확정되지 않은 몬스터의 `itemDrops`는 비워 두고, 이후 데이터 작업에서 개별 설정할 수 있도록 했다.

### 3. 전투 드롭 판정 서비스 구현

`BattleDropService`를 추가했다.

전투 승리 시 실제 전투에 참가한 적 몬스터들의 DropTable을 순회해 다음을 판정한다.

- 몬스터별 골드 범위 난수 판정
- 아이템별 확률 판정
- 드롭 수량 판정
- 여러 몬스터가 같은 아이템을 떨어뜨렸을 때 수량 합산
- 여러 몬스터의 골드 합산

아이템 ID가 없는 잘못된 데이터나 비어 있는 DropTable은 안전하게 무시한다.

### 4. 보상 전용 RNG 분리

전투 명중·피해 등에 사용하는 `CombatRng`와 별개로 `RewardRng`를 추가했다.

따라서 전투 판정 난수와 보상 드롭 난수가 서로 직접 영향을 주지 않도록 구조를 분리했다.

### 5. 전투 드롭 결과 보존

`BattleDropResult`와 `BattleDropItemResult`를 추가했다.

전투에서 판정된 다음 정보를 하나의 결과로 보존한다.

- 획득 예정 골드
- 획득 예정 아이템
- 아이템 ID
- 아이템 표시 이름
- 아이템 수량

`ExplorationMonsterEncounterController`에는 `LastBattleDropResult`를 추가했다.

승리가 확정되면 드롭을 한 번만 판정하며, 이후 보상 화면이 열리더라도 다시 굴리지 않고 이미 결정된 결과를 사용할 수 있도록 했다.

현재 일차에서는 드롭 **판정과 결과 보존**까지 구현했으며, 실제 인벤토리와 플레이어 골드에 최종 지급하는 처리는 이후 보상·인벤토리 시스템과 연결한다.

### 6. 테스트용 드롭 데이터 추가

`MON_TEST`에는 시스템 검증을 위한 테스트 아이템을 연결했다.

- 아이템 ID: `ITEM_DAY80_TEST_DROP`
- 드롭 확률: 100%
- 수량: 1개

이를 통해 실제 전투 승리 흐름에서 아이템 드롭 결과가 생성되는지 확인할 수 있다.

### 7. EditMode 테스트 추가

`BattleDropServiceTests`에 다음 7개 테스트를 추가했다.

1. DropTable이 없는 몬스터는 드롭 없음
2. 0% 아이템은 드롭되지 않음
3. 100% 아이템은 항상 드롭
4. 골드 최대값 포함 여부
5. 여러 몬스터의 골드와 동일 아이템 수량 합산
6. basis point 확률 경계값 판정
7. RNG가 null일 때 예외 처리

테스트 코드는 저장소에 포함되어 있으며, GitHub에서는 별도의 CI 실행 상태가 등록되어 있지 않으므로 Unity Test Runner 통과 여부를 이 개발일지에서 단정하지 않는다.
