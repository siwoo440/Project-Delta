# 1일차 기본 실행 구조 설계

사용자가 설명을 확인한 뒤 1일차 구현·커밋·푸시를 승인한 범위를 기록한다.

---
## 목표와 범위

Bootstrap → Title → 새 게임 → Dungeon 흐름과 중복 초기화 방지, 상태별 입력 분리를 구현한다. 이동·전투·저장 기능은 이후 개발 범위다. 기존 기능의 규칙을 기준으로 C# 코드를 새로 작성한다.

---
## 구현 방식

현재 D:\Project-Delta의 새 2D 프로젝트를 사용한다. 기존 저장소에서 코드를 이식하는 방식과 비교했으며, 사용자가 새 코드 작성을 지정했으므로 새 프로젝트 기반을 선택했다. 원격 저장소는 커밋이 없는 빈 저장소로 확인했다.

Core의 순수 상태 모델, Runtime의 AppRoot·씬 로더·입력 라우터·화면, Editor의 씬 생성·빌드 도구로 역할을 나눈다. 실행 중 공통 객체는 하나만 유지한다. 전환 시작 시 입력을 잠그고 중복 요청을 거절한다.

---
## 환경과 화면

Unity 6000.3.21f1, URP 2D, Unity Input System, uGUI, Windows 64비트 기준이다. 타이틀은 새 게임 버튼, 던전은 정지한 격자와 플레이어 표시를 제공한다. 던전의 Esc는 타이틀 복귀에 사용한다. 기본 화면 문구는 한국어이며 Windows 기본 한글 글꼴을 실행 시 사용한다.

---
## 완료 기준

- 타이틀 진입, 새 게임으로 던전 진입, Esc로 타이틀 복귀.
- 전환 중 중복 요청 및 초기화 객체 중복 방지.
- 타이틀 UI 입력과 던전 탐험 입력의 동시 활성화 방지.
- EditMode·PlayMode 검증 및 Windows 시험 빌드.
- 원격 기존 이력 덮어쓰기 없이 첫 커밋과 푸시.
