# Project Delta - 77일차 개발일지

## 작업 주제

**기획서 몬스터 20종 데이터화 및 그룹 시스템 실제 콘텐츠 연결**

---

## 개발 목표

76일차에 만든 몬스터 그룹 구성 시스템(등급 기반 대표 외형 판정)은 구조만 갖춰져 있고, 실제 몬스터 콘텐츠가 없어 항상 "1마리"로만 동작했다. 77일차는 기획서에 정리된 실제 몬스터 종을 `MonsterDefinition` 데이터로 만들고, 그중 하나를 실제 `EncounterDefinition`에 연결해 그룹 시스템이 눈에 보이게 동작하도록 만든다.

수치는 정확한 밸런스가 아직 없어 **전부 임의값**으로 채웠다. 이후 조정 시 각 에셋의 능력치 필드만 바꾸면 된다.

---

## 1. 기획서 몬스터 목록 확인

기획 문서에서 확인한 몬스터는 총 20종이다.

**일반 개체 16종**
```text
슬라임 / 고블린 / 아라크네 / 라미아 / 하피 / 서큐버스 / 미믹 / 알라우네 /
고스트 / 리자드 / 늑대 수인 / 고양이 수인 / 여우 수인 / 토끼 수인 / 곰 수인 / 쥐 수인
```

**상위 개체(보스급) 4종**
```text
슬라임 퀸 (1층) / 고블린 퀸 (2층) / 미노타우르 (3층) / 용 수인 (4층)
```

문서에는 층별 배치(1층: 슬라임·슬라임 퀸, 2층: 고블린·고블린 퀸, 3층: 미노타우르, 4층: 용 수인, 5층: 별도 마왕)와 "일반 몬스터는 3~4개, 상위 개체는 4개 이상의 스킬 보유" 같은 정보도 있었지만, 구체적인 능력치·스킬 데이터는 "부록 A. 캐릭터 상세 데이터"에서 별도로 관리된다고만 적혀 있어 아직 확정된 수치는 없다.

---

## 2. MonsterDefinition 20종 생성

`Assets/ProjectDelta/Data/Monster/Monster Definition/`에 종별로 에셋을 만들었다. 76일차에 추가한 `Rarity` 필드는 다음 기준으로 채웠다.

```text
일반 개체 16종 → Normal
상위 개체(퀸·미노타우르·용 수인) 4종 → Boss
```

능력치는 전부 임의값이다. 대략적인 방향만 잡았다.

```text
일반 개체: HP 11~20 선, 종별 컨셉에 맞춰 속도·회피·매력만 다르게
  (하피·수인 계열은 속도·회피 높게, 곰 수인은 HP·방어 높게, 서큐버스는 매력 높게 등)
상위 개체: HP 60~110, 공격·방어·속도 전반적으로 일반 개체보다 큰 폭으로 상향
```

AI Profile은 전부 62일차에 만든 `DefaultTestMonsterAiProfile`을 임시로 연결했다 — 종별 AI 성향은 아직 확정되지 않아, 나중에 74일차 `MonsterAiProfile` 구조로 종마다 다르게 채우면 된다.

---

## 3. EncounterDefinition에 실제 콘텐츠 연결

기존 `EncounterDefinition.asset`(`ENC_TEST_MONSTER`)을 테스트 몬스터 대신 실제 1층 몬스터로 바꿨다 — 문서의 "1층: 슬라임, 슬라임 퀸" 배치를 그대로 반영한 최소 예시다.

```text
monster (1번 자리, 항상 존재): 슬라임
additionalMonsterPool (2번 자리부터):
  슬라임 weight 5  (같은 무리가 계속 나올 확률이 높음)
  슬라임 퀸 weight 1 (드물게 섞여 나옴 - 등급이 높아 대표 외형이 바뀜)
minGroupSize: 1
maxGroupSize: 3
```

이 설정으로 방마다 슬라임 1~3마리가 나오고, 낮은 확률로 그중 하나가 슬라임 퀸으로 바뀐다. 슬라임 퀸이 포함된 방은 76일차 대표 판정 규칙에 따라 탐험 화면에 슬라임 퀸이 대표 외형으로 보인다.

기존 테스트용 `MonsterDefinition.asset`(`MON_TEST`)은 그대로 남겨뒀다 — `ExplorationMonsterEncounterController.testMonsterDefinition`이 여전히 이 에셋을 참조하고 있고, 76일차에 만든 `ResolveMonsterDefinition()`의 최종 안전망(조회 실패 시 대체)으로 계속 쓰이기 때문에 지울 필요가 없다.

---

## 변경 파일

```text
Assets/ProjectDelta/Data/Monster/Monster Definition/*.asset (신규 20종 + .meta)
Assets/ProjectDelta/Data/Monster/Encounter Definition/EncounterDefinition.asset (수정)
```

새 스크립트나 로직 변경은 없다 — 76일차에 만든 구조가 실제 콘텐츠를 그대로 받아들일 수 있는지 확인하는 순수 데이터 작업이다.

---

## 확인 사항

- 기획서에 정리된 몬스터 20종(일반 16 + 상위 개체 4)을 전부 `MonsterDefinition` 데이터로 만듦
- 상위 개체 4종은 `Rarity.Boss`, 나머지는 `Rarity.Normal`로 지정
- 능력치·AI Profile은 전부 임의값/기본값 — 정확한 수치는 "부록 A" 확정 후 반영 예정
- 기존 `EncounterDefinition`을 1층 콘텐츠(슬라임 무리 + 드문 슬라임 퀸)로 교체해 76일차 그룹 시스템이 실제로 동작하는 예시를 만듦
- 기존 테스트 몬스터(`MON_TEST`)와 그 AI Profile은 안전망으로 남겨둠, 삭제하지 않음
- 코드 변경 없음(순수 데이터 작업) — 새 EditMode 테스트도 추가하지 않음 (다른 콘텐츠 전용 일차와 같은 관례)

Unity Editor에서 이 데이터가 실제로 어떻게 보이는지(슬라임 무리가 나오는지, 가끔 슬라임 퀸이 대표로 보이는지)는 직접 플레이해서 확인이 필요하다.

---

## 이번 일차 완료 상태

77일차 목표인 **기획서 몬스터 20종 데이터화 및 1층 콘텐츠 연결**을 완료했다. 76일차에 만든 구조 위에 처음으로 실제 몬스터 콘텐츠가 올라갔다.
