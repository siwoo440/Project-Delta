# 프로젝트 델타

2D 탑뷰 격자 탐험과 별도 턴제 전투, 선택·관계 중심 로그라이트 프로젝트.

기존 기획의 기능과 규칙을 기준으로 코드를 새로 작성한다. 현재는 기본 실행 흐름, 2D 격자 이동, 무작위 던전, 2층 이동, 미니맵과 자동 조우 후 시험 전투 라운드를 제공한다.

## 실행

Unity Hub에서 저장소 폴더를 프로젝트로 추가하고 `Assets/ProjectDelta/Scenes/BootstrapScene.unity`를 열어 Play를 실행한다.

타이틀에서 새 게임을 선택하면 던전에 진입한다. 던전에서 WASD·방향키·게임패드 방향 입력으로 한 칸씩 이동하고, Esc 또는 게임패드의 취소 버튼으로 타이틀에 복귀한다. 흰 화살표는 바라보는 방향, 붉은 칸은 장애물, 노란 화살표는 문이다. 문 앞에서 문 방향으로 마지막 이동을 마친 뒤 E 또는 게임패드의 남쪽 버튼을 누르면 다른 방으로 이동한다. 도착 직후 돌아가려면 방 안쪽으로 한 칸 이동한 뒤 문 쪽으로 돌아와 상호작용한다. 계단 방 중앙의 파란 화살표에 서서 E 또는 게임패드 남쪽 버튼을 누르면 다음 층으로 이동한다. 상위 개체 방에서 분홍 대상 주변 한 칸에 이동을 마치면 시험 전투가 시작된다. 시험 전투에서 행동 순서와 라운드를 진행할 수 있으며, 시험 종료 후 같은 위치로 복귀한다. 실제 전투 판정과 저장은 후속 작업이다.

오른쪽 위 미니맵은 현재 방과 방향을 초록색으로, 방문한 방을 밝은색으로 표시한다. 연결만 확인한 미방문 방은 어두운 윤곽으로 나타나며, 아직 확인하지 못한 방과 비밀 통로는 숨긴다. 새 게임을 시작하면 방문 기록이 초기화된다.

새 게임마다 일반 방 8~10개와 시작 방·계단 방·상위 개체 방이 연결된 1층 구조를 생성한다. 2층도 임시로 같은 생성 규칙을 사용하며 이전 층으로 돌아갈 수 없다. 3층과 실제 전투 행동은 후속 작업이다.

## 코드 구성

| 폴더 | 역할 |
|---|---|
| Assets/ProjectDelta/Core | Unity 객체에 의존하지 않는 게임 상태 규칙 |
| Assets/ProjectDelta/Runtime | 초기화·씬 전환·입력·화면 표시 |

## 검증과 빌드

PowerShell에서 `Tools/Run-DayEightChecks.ps1 -Check EditMode`, `-Check PlayMode`, `-Check Build`로 실행한다. 편집기 경로가 다르면 `-UnityPath`로 지정한다. 플레이 화면을 창을 띄우지 않고 캡처하려면 `-Check Screenshot`을 사용한다. Windows 테스트 실행 파일 검증은 `-Check PlayerTests`를 사용한다. 원본 프로젝트가 Unity에서 열려 있으면 별도 프로젝트 복사본에서 테스트한다.

기본 씬 재생성은 Unity 메뉴 `Project Delta/1일차/기본 씬 재생성`으로 실행한다. 생성기는 해당 기본 씬 세 개를 덮어쓰므로 씬 편집 후에는 변경을 먼저 보존한다.

기존 던전에 이동 요소를 다시 연결하는 메뉴는 `Project Delta/2일차/던전 이동 구성`이다. 바닥이 완전히 비어 있을 때만 시험 바닥·장애물을 생성하며, 기존 바닥의 빈 칸과 사용자 장애물은 보존한다. 이전 시험 장애물과 정확히 일치하는 배치는 밝은 전용 타일로 교체한다. 다른 열린 씬의 미저장 변경은 저장 또는 취소를 확인한다.

두 시험 방을 연결하는 메뉴는 `Project Delta/3일차/시험 방 연결`이다. 기존 객체나 문 위치의 타일과 충돌하면 구성을 중단한다. 다른 열린 씬의 미저장 변경은 저장 또는 취소를 확인한다.

세 번째 방과 지도를 구성하는 메뉴는 `Project Delta/4일차/시험 방과 지도 구성`이다. 기존 방·문 설정이 시험 구성과 다르거나 새 출구 칸이 점유되어 있으면 구성을 중단한다.

검증 기록은 `Artifacts`, 8일차 Windows 빌드는 `Builds/Day08`에 생성되며 Git에서 제외한다. 기존 빌드도 각 일차의 경로에 남는다.
